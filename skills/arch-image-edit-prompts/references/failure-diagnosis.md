# 실패 진단

증상 → 관찰된 원인 → 프롬프트 수정. 대부분은 "무엇을 지킬지"를 이름 붙여 적지 않아서 생긴다.

근거의 종류가 둘이다. 수정 열에 "실행 기록 cases/…"가 붙은 행은 이 저장소의 증거 갤러리에서 확인한 것이다. 나머지 행은 작성자가 실무 편집 작업에서 반복해 겪은 관찰이며, 저장소에 재현 기록이 없다. 후자는 가설로 읽고 자기 사례에서 확인한다.

| 증상 | 관찰된 원인 | 수정 |
|---|---|---|
| **시점이 틀어짐.** 재생성마다 카메라가 조금씩 이동·회전 | 같은 대화에서 편집을 거듭하면 직전 결과가 기준이 되어 오차가 누적 | 새 대화에서 원본을 다시 첨부하고 완결형 프롬프트로 시작. 카메라 구획에 "건물 모서리와 지평선 위치 유지" 명시 |
| **매스가 수직으로 펴짐.** 기울어진 입면이 직각으로 바뀜 | "매스 유지" 한 단어로는 모델이 정형화된 매스를 선호 | 기울기·필로티 높이·분절선 수를 숫자로. 기준 이미지를 이미지 1로 두고 "이미지 1의 형태가 기준"이라고 선언 |
| **층수가 바뀜** | 비율만 맞추고 층수는 자유롭게 채움 | 동별 층수를 숫자로. 캡처에 분절선이 없으면 프롬프트 전에 사용자에게 확인 |
| **참조 이미지 역할이 뒤바뀜.** 디자인을 유지할 이미지의 뷰를 바꾸고, 뷰만 참고할 이미지의 디자인을 가져옴 | 두 이미지의 역할을 첫 줄에 선언하지 않음 | 역할 선언 구획 추가. "형태는 가져오지 않는다"를 참고 이미지마다 붙임 |
| **주석 색이 실제 색으로 칠해짐** | 빨간 선·노란 박스를 디자인 지시로 해석 | "표시 색은 실제 색이 아니라 설명 기호"를 주석 이미지 설명 첫 줄에 |
| **요청하지 않은 요소 추가.** 물방울, 소품, 영문 장식 문구, 간판, 조경 | 편집 정밀도가 높은 모델에서 더 자주 관찰. 빈 공간을 채우려는 경향 | 금지 목록을 구체적으로. "새 소품·문구·장식을 추가하지 않는다" |
| **이미지 안 글자가 바뀜.** 건물명·표지가 다른 이름으로 | 글자를 고정 대상으로 선언하지 않음 | 고정 목록에 글자 원문을 따옴표로 인용. 글자가 없어야 하면 "글자를 넣지 않는다" |
| **부분 편집인데 다른 요소도 사라짐.** 슬라브·벽체·창호가 없어짐 | 변경 범위를 영역으로 한정하지 않음 | "표시 영역 밖의 모든 요소는 원본과 동일" + 주석 이미지(유형 D) 사용 |
| **반복 모듈이 계속 틀림.** 프레임 기울기 방향, 루버 간격 | 그림만으로는 모듈 규칙을 못 읽음 | 유형 F로 왼쪽 첫 단위부터 순서대로 서술. 필요하면 영어 병기 |
| **두 면을 따로 처리해 사이가 비거나 어긋남** | L자·꺾인 면을 별개 면으로 인식 | "하나의 연속 면으로 보고 끊김 없이" 명시 |
| **패턴이 모자이크처럼 보임.** 건축 논리 없이 장식만 | 패턴 규칙만 있고 개구부·구조 논리가 없음 | 개구부 위치·크기 규칙, 구조 부재와의 관계를 함께 서술. 시공 가능성 조건 추가 |
| **결과가 매번 비슷함.** 사선 강조, 단조로운 톤 반복 | 변수를 바꾸지 않고 재요청 | 바꿀 변수를 하나씩 명시적으로 지정. 색 범위, 개구부 비율, 밀도 그라데이션 방향 |
| **질감 드리프트.** 같은 원본을 3회 이상 편집하면 표면이 거칠어지거나 지나치게 매끈해짐 | 편집 누적 | 원본에서 다시 시작. 여러 수정은 한 프롬프트에 묶어 1회 편집 |
| **확대하면 뭉개짐.** 붓터치, 물감 자국 같은 표현 | 생성 해상도 한계. 후처리 업스케일은 선명도만 올리고 표현은 못 고침 | 검토용으로만 사용. 타일 분할 재생성은 이음매 문제로 권장하지 않음. 최종본이 필요하면 다른 제작 경로를 검토 |
| **비율 보정에서 디자인이 바뀜** | "보정"을 "재디자인"으로 해석 | 첫 줄에 "디자인 생성이 아니라 비율·구도 보정" 선언(유형 E) |
| **같은 건물의 인접 부위가 함께 바뀜.** 외장만 바꿨는데 필로티 기둥·옥탑도 변함 | 변경 대상을 건물 단위로 써서 부위 경계가 없음 | 변경 문장에 제외 부위를 붙임: "필로티 기둥과 커튼월은 현재 재질 유지". 실행 기록 cases/01 |
| **깊이 방향 기울기가 입면 사선으로 그려짐.** 벽에서 튀어나온 핀이 V·X자 교차 핀이 됨 | 정면에 가까운 뷰에서 깊이는 보이지 않아 모델이 "기울기"를 화면 안 사선으로 표현 | "이 뷰에서 핀은 모두 수직선으로 보인다, 서로 교차하지 않는다"를 명시하고 깊이 변화는 그림자 폭으로 서술. 실행 기록 cases/05 |
| **정량 지시가 반영되지 않음.** "채도 30% 감소"가 거의 변화 없음 | 편집 모델은 수치를 강도로 해석하지 않음 | 상대 표현("주변은 뒤로 물러나고 대상만 앞으로")과 참고 이미지 병용. 실행 기록 cases/06 |
| **영역 경계가 ±1층 어긋남.** 마크업 사각형보다 넓게 적용 | 사각형은 "이 부근"으로 해석됨 | 경계를 이미지 안의 선(발코니 슬래브, 층 분절선)으로 지정. 실행 기록 cases/04 |
| **검사에서 화면 전체가 누출로 표시됨** | 생성형 편집기가 전체를 재렌더해 잎·그림자·질감이 미세 변동 | 실패가 아님. 구조 단위 지표로 다시 보고 외곽선·층수로 판정. 픽셀 지표는 같은 원본의 결과 간 비교에만 |

## 판단 규칙

- 같은 증상이 두 번 반복되면 프롬프트를 고치지 말고 **새 대화**로 간다.
- 실패 이미지를 다음 편집의 입력으로 쓰지 않는다. 항상 승인된 이미지에서 시작한다.
- 한 번에 바꾸는 변수는 하나. 실패 원인을 분리하기 위해서다.
- 고친 프롬프트는 어떤 증상을 막기 위해 어떤 줄을 추가했는지 기록한다. 같은 프로젝트에서 재사용된다.
